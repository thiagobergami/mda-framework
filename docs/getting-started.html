Getting Started

Install the framework, scaffold your first game concept, and validate it in under 5 minutes.

Prerequisites

  • Node.js >= 18 (for the CLI and Spec Wizard)
  • npm (comes with Node.js)
  • Optional, for the MDA Studio: Node.js ≥ 20 and pnpm 9.x

Installation

git clone <this-repo>
cd framework
npm install

This installs the mda CLI tool locally. All commands are run via npx mda.

Quick Start

  1. Scaffold a game concept 
    npx mda new concept "My Game"

    This creates specs/concept/my-game.concept.md with a full template and auto-assigned ID.

  2. Fill in the template

    Open the generated file and fill in each section: Vision, Aesthetic Profile, Core Loop, Target Audience, Feature Map, and Boundaries. See the Concept Schema for guidance.

  3. Run the concept readiness gate 
    npx mda gate concept

    The gate checks 6 quality criteria. Fix any failures before proceeding.

  4. Scaffold the next layer 
    npx mda new aesthetic "Core Feature"

    Continue through the layers: aesthetic → dynamic → mechanic → tuning → asset → binding.

  5. Validate all specs 
    npx mda validate

    Runs 8 validation rules to check structural integrity across all spec layers.

  6. (Optional) Boot the Studio to see your tree

    Once you have a few specs, the MDA Studio renders them as a live tree with issues, costs, validator warnings, approvals, and an activity log. From the mda-studio/ workspace, in two terminals: 

    # terminal 1 - API server (registers your game from env vars)
cd mda-studio
MDA_STUDIO_GAME_ID=my-game \
MDA_STUDIO_GAME_NAME="My Game" \
MDA_STUDIO_GAME_SPECS_ROOT=/abs/path/to/your/repo \
MDA_STUDIO_GAME_CONCEPT_PATH=specs/concept/my-game.concept.md \
MDA_STUDIO_GAME_PRIMARY_AESTHETIC=Fellowship \
MDA_STUDIO_GAME_CONCEPT_TITLE="My Game" \
pnpm install && pnpm --filter @mda-studio/server dev

# terminal 2 - UI
pnpm --filter @mda-studio/ui dev

    Then open http://127.0.0.1:3101. Click your game card to enter its spec tree.

    See the Studio Operator Guide for the full reference.

Project Structure

specs/                              # Specification layer
├── WORKFLOW.md                     # 8-step process: idea -> implementation
├── glossary.md                     # Shared MDA vocabulary
├── traceability.md                 # Bidirectional links between all specs
├── concept/_schema.md              # Game vision, aesthetic profile, feature map
├── aesthetics/_schema.md           # Player experience goals (observable proxies)
├── dynamics/_schema.md             # Feedback systems, invariants, interaction patterns
├── mechanics/_schema.md            # Player affordances, rules, behavioral contracts
├── tuning/_schema.md               # Parameter ranges, trade-offs, iteration logs
├── assets/_schema.md               # Emotional intent, technical reqs, placeholders
└── bindings/
    ├── _schema.md                  # Engine-specific mapping specs
    └── equivalence.md              # Cross-engine concept mapping table

tools/                              # CLI tooling (TypeScript)
├── src/
│   ├── cli.ts                      # Commander-based CLI entry point
│   ├── parser.ts                   # Frontmatter parser with scope discovery
│   ├── graph.ts                    # Spec adjacency-list graph builder
│   ├── reporter.ts                 # Terminal and JSON output formatting
│   ├── scaffold.ts                 # Spec template generation
│   ├── types.ts                    # Core type definitions
│   ├── rules/                      # 8 validation rules
│   └── gates/                      # 5 quality gates
└── dist/                           # Compiled output (git-ignored)

src/                                # Runtime tools (Luau)
├── shared/MDALogger.luau           # Structured logging with MDA layer tagging
└── tools/validate-specs.luau       # Legacy Luau spec validator

mda-studio/                         # Operator surface (pnpm workspace)
├── packages/shared/                # Zod wire-contracts (server <-> UI)
├── server/                         # Express API + in-memory stores + SSE
├── ui/                             # Vite + React spec-tree-first UI
└── docs/                           # Operator + architecture guides

design/mda-studio/                  # Design docs for the studio itself
└── spec-tree-ui/plan.md            # The plan the UI was built against

CLAUDE.md                           # AI instructions (read by Claude Code)

Working with AI

The framework is designed to be used with AI coding assistants, particularly Claude Code. The CLAUDE.md file in the project root contains comprehensive instructions that Claude reads automatically.

Tip

When using Claude Code, just describe your game idea. Claude will read the CLAUDE.md instructions, follow the workflow, create specs layer by layer, run gates, and implement the code — all while maintaining full MDA traceability.
