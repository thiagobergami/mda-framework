Spec Wizard

An interactive CLI that walks you through Concept → Aesthetics → Dynamics → Mechanics → Assets → Tuning → Levels, branching its menu off the current state of specs/. Source: design/pipeline/cli/.

Run: npm run spec
Type-check: npm run spec:check
Stack: Node + tsx + @inquirer/prompts

Why use it

The bare mda new <layer> <name> CLI scaffolds an empty template. The wizard adds two things on top:

  1. Branched menus — only offers what makes sense given the current state of specs/. You won't see "Add a mechanic" until at least one dynamic exists.
  2. Frontmatter pre-fill — asks high-level questions (primary aesthetic, traces, level status) and patches the answers into the scaffolded file so you start with the body, not metadata.

The wizard shells out to mda new for actual file creation. Any change to mda new's templates flows through automatically.

Flags

FlagEffect
--dry-runPrint what mda commands would run; write nothing
--dir PATHOperate on a different project root (default: cwd)

Menu Branching

The top-level menu is computed on each iteration from listExistingSpecs():

  • If specs/concept/ is empty → only "Start a new concept" is offered.
  • If a concept exists but no aesthetics → "Add an aesthetic" appears (with a "/3+ recommended" hint).
  • If aesthetics exist → "Add a dynamic" appears.
  • If dynamics exist → "Add a mechanic" appears.
  • If mechanics exist → "Add an asset", "Add a tuning spec", and "Design a level" all appear.
  • "Validate all specs" and "Exit" are always available.

Per-Layer Prompts

Each prompt asks for high-level fields, scaffolds via mda new, then patches frontmatter:

LayerAsks forPatches into frontmatter
ConceptName, pitch, platform, primary + secondary aestheticsplatform, primary_aesthetic, secondary_aesthetics, pitch
AestheticName, primary category, target audienceprimary_aesthetic, target_audience
DynamicName, which AES specs it serves (multi-select from existing)traces_to_aesthetics
MechanicName, which DYN specs it producestraces_to_dynamics
AssetName, target MECs, statustraces_to_mechanics, status
TuningName, target MEC + DYN + AES specstraces_to_mechanics, traces_to_dynamics, traces_to_aesthetics
LevelName, status, AES + DYN + MEC + AST refs, durationstatus, estimated_duration, full references: block

Architecture

design/pipeline/cli/
├── index.ts                # entry point, top-level menu, --dry-run
├── prompts/
│   ├── concept.ts
│   ├── aesthetic.ts
│   ├── dynamic.ts
│   ├── mechanic.ts
│   ├── asset.ts
│   ├── tuning.ts
│   └── level.ts
├── lib/
│   ├── existingSpecs.ts    # reads specs/ + design/levels/ for menu branching
│   ├── extractIds.ts       # parses (id, name) pairs for trace prompts
│   └── patchFrontmatter.ts # writes wizard answers into scaffolded files
├── tsconfig.json           # type-check only (run via tsx)
└── README.md

The wizard runs through tsx, so there's no build step — iterate on prompts and re-run npm run spec immediately.

Adding a New Prompt

  1. Copy an existing prompts/<layer>.ts as a starting point.
  2. Replace the layer name, prompt questions, and which existing IDs to read via extractIds().
  3. Use patchFrontmatter() for flat-key fields. For nested blocks like the level references:, hand-edit via a regex replace inside the prompt.
  4. Import and dispatch from index.ts — add a case to the topMenu() choices and switch.
