# V1-lite — Operator front door without agents

## Decision

The studio ships an explicit intermediate milestone, **V1-lite**, that
sits between the current state and full V1 (agents, scheduler,
watchdog, cost gating). V1-lite is the deliverable of plan.html
weeks 2–6.

V1-lite delivers the **operator front door** with persistence, but
**no agent runtime**.

## Scope of V1-lite

In:

- CLI machine-readable flags (`--json`, `--no-prompt`, `--from-json`)
  across `mda new`, `validate`, `gate`, `asset-plan *`.
  *(Plan week 2.)*
- `mda-runner` service in the studio server that spawns the CLI and
  parses its JSON output. *(Plan week 3.)*
- Chokidar-based file watcher that invalidates the spec-tree cache
  and fans changes out over SSE. *(Plan week 3.)*
- "Validate" button + per-row "Run gate" in the studio chrome.
  *(Plan week 3.)*
- "Register a game" form in the studio (replaces env-var bootstrap as
  the primary path). *(Plan week 4.)*
- "+" CTA on tree nodes creates real specs via `mda new`.
  *(Plan week 4.)*
- Drizzle-kit wired with four tables: `games`, `issues`,
  `cost_events`, `approvals`. *(Plan week 5.)*
- pglite by default for embedded mode (see
  [[2026-05-27-embedded-db]]). *(Plan week 5.)*
- `mda-studio onboard --demo` single command from clean clone to a
  populated studio. *(Plan week 6.)*
- Asset-plan generate/exec/import surfaced in the UI with NDJSON
  streaming. *(Plan week 6.)*

Out (deferred to post-V1-lite, original M3+):

- Agent runtime, adapters, scheduler, heartbeat, watchdog.
- Cost budgets / pause / spend gating per game.
- `claude_local` / `codex_local` adapters.
- Log shipper plugin (see REVIEW RT1).
- Multi-engine support (see [[2026-05-27-multi-engine]]).

## Why an explicit V1-lite

The original plan goes from "stub schema" to "agents + budgets + log
shipping" in M1–M6. That arc has no natural shippable checkpoint
between "nothing persists" and "full agent runtime". V1-lite carves
out the bottom half — *operator front door with state* — so the next
6 weeks have a real deliverable on which agents can later be built.

Without V1-lite, the agent work in M3 lands against an in-memory
registry and a CLI no program can drive, and we will have to retrofit
both anyway.

## What V1-lite proves

- The hybrid front door from [[2026-05-27-front-door]] is real: a user
  can author specs from the CLI **or** from the studio with no
  shell required.
- The CLI is driveable as an adapter (the seed of the future
  `AgentAdapter` interface).
- The studio survives a restart with operator state intact.
- An operator can go from clean clone to a populated studio in
  under 60 seconds.

## What V1-lite does NOT prove

- That agents work. They don't exist yet.
- That cost gating works. The `studios` table loses its pause/budget
  columns in plan task D5.Q4; they come back in M4.
- That multi-engine support works. See [[2026-05-27-multi-engine]].

## Sequencing change

`design/mda-studio/plan.md` §4 gains a "V1-lite (operator front door)"
milestone above the existing M1 list. §10 (sequencing) places V1-lite
first, with M1–M6 picking up afterwards. This edit lands in plan task
D1.S3.

## Acceptance (V1-lite is done when…)

From plan.html week-5 gate, plus week-6 deliverables:

1. Fresh `pnpm install` → `pnpm mda-studio onboard --yes --demo` →
   browser opens on a populated home in under 60 seconds.
2. Operator can register a game, create a spec, log a cost event,
   restart the server, and find everything intact.
3. Asset-plan generate/exec/import can be driven from the UI on a
   real AST spec; progress streams via SSE.
4. `npx mda validate --json` and `npx mda gate <layer> --json` are
   driveable by an external program with no TTY.
